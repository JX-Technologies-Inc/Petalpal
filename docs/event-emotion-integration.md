# Frozen Event emotion integration

The frozen incumbent remains `goemotions-targeted-v1/experiment/epoch-1-checkpoint`. This integration uses its validated FP32 ONNX export, Product-18 projection at the frozen 0.35 cutoff, and `selectFlowerSecondaryEmotions`. It does not change the model, selector, datasets, or ML quality claims. Final was not accessed for this integration.

The incumbent is historical, **research-only**, and its underlying training-text rights remain unresolved. **Production-approved classifier: NONE.** A local successful inference does not grant production approval. `primaryGardenMood` is authoritative user input; `secondaryEmotions` are inferred, unconfirmed metadata and must never replace or be described as a user-confirmed Primary.

`EMOTION_CLASSIFIER_ENABLED` defaults to off. Only authenticated `/events` saves and the development preview route can call the Event adapter. Daily Grow Journal and social routes do not. A caller may supply an optional canonical `primaryGardenMood` on `/events`; it remains user chosen. When provided, a Flower is created with the deterministic Flower Engine even when classification is off or fails. An Event without a Primary retains its emotion labels but has no Flower. Event enrichment, the optional Flower, and Event Memory are owner scoped; a unique Flower `sourceEventId` and the existing Event idempotency key prevent retry duplication. Memory extraction reads Event emotion fields and does not invoke a report LLM during Event creation.

The server permits this research incumbent only when `NODE_ENV` is `development` or `test` **and** `EMOTION_CLASSIFIER_ENABLED=true`. In every other environment, including production, the flag cannot enable it; inference is skipped with `RESEARCH_ONLY_CONTEXT`. The server gate applies to ordinary `/events` as well as the preview route. The development Lab and ordinary Event path use the same selector semantics.

Event persists `emotionStatus`, an explicit `emotionOutcome` (`ABSTAINED`, `INFERRED_1`, `INFERRED_2`, `SKIPPED`, or `FAILED`), `emotionProvenance=INFERRED_UNCONFIRMED` for attempted inference, model ID/version, `emotionModelStatus=research_only`, and available per-label probabilities. Skipped inference has no model provenance. No confidence is fabricated. Existing rows retain their prior semantics through nullable new fields and the `SKIPPED` outcome default. EventMemory copies these fields from its source Event without treating labels as confirmed. The Flower uses Primary for species and secondary labels only for visual modifiers; Garden displays them as inferred. EventMemory embedding input is the Event text summary (optionally topics/people), not emotion fields. Semantic retrieval and Weekly/Monthly narrative evidence use summaries and source IDs, not inferred labels.

`SUCCESS` with zero labels is a valid abstention and persists as `ABSTAINED`; one or two labels persist as `INFERRED_1` or `INFERRED_2`. Disabled or blocked inference is `SKIPPED`; runtime or invalid-output failure is `FAILED`. All three may have an empty `secondaryEmotions` array, so consumers must inspect outcome rather than infer it from array length. Memory extraction defers while an Event is `PENDING`; after bounded retries, the worker finalizes a stale `PENDING` Event as `FAILED` with no inferred labels before extracting memory.

## Local development and Auth E2E

1. Provide a separate local PostgreSQL database whose name contains `dev`, `development`, or `test`. Set `DEV_DATABASE_URL` in the Git-ignored root `.env` file. Development fails closed without it and does not fall back to `DATABASE_URL`. Keep the production `DATABASE_URL` configuration unchanged. Apply migrations only to the new development database and run `npx prisma generate`.
2. In Firebase Console for `petalpal-b212c`, use **Project settings → Service accounts → Firebase Admin SDK → Generate new private key**. Save the downloaded JSON outside the repository with owner-only file permissions. In the Git-ignored root `.env.auth-e2e.local`, set `GOOGLE_APPLICATION_CREDENTIALS=/absolute/path/to/petalpal-b212c-service-account.json`. The existing backend Admin initialization uses Application Default Credentials from this path. Never commit the JSON or copy its contents into a tracked file.
3. In the same `.env.auth-e2e.local`, set `AUTH_E2E_TEST_EMAIL` and `AUTH_E2E_TEST_PASSWORD` for the dedicated test account. Use `.env.auth-e2e.example` as a placeholder-only template. In Git-ignored `client/.env.development.local`, use the existing PetalPal Firebase web configuration and `VITE_API_BASE_URL=http://localhost:3000`.
4. Ensure the local FP32 artifact is available at `experiments/emotion-classifier-v2/v4/aligned-supervision-v1/goemotions-targeted-v1/onnx-cpu/artifacts/model-fp32.onnx`, with the frozen checkpoint tokenizer/config at `experiment/epoch-1-checkpoint`. Set `EMOTION_CLASSIFIER_ENABLED=true` in the ignored root `.env` when testing classification. Keep `AI_REQUEST_TIMEOUT_MS` bounded (default 3000).
5. From the repository root, run `npm run dev:emotion-lab`. This starts the development backend and Vite frontend. Sign in at `http://127.0.0.1:5173/`, then open `http://127.0.0.1:5173/dev/emotion-lab` on the same origin.
6. For the dedicated real Firebase Auth E2E workflow, run `npm run test:auth:e2e` from the repository root. It uses the configured test account, waits at the inbox boundary when needed, and resumes from its Git-ignored local state. The workflow may create or replace only that exact test account and its matching development database data.

For a manual Event smoke, preview a short Event, then save it with a chosen Primary. Confirm one Event ID, 0–2 Product-18 labels, one Flower, and matching color/effect. Repeat the save with the same `Idempotency-Key` to confirm no second Flower or inference attempt. Verify another account receives 404 for the Event ID. With `EMOTION_CLASSIFIER_ENABLED=false`, preview should report `SKIPPED`, no labels, and a no-secondary Flower preview; Event save should still succeed.

## Deployment blocker

The FP32 ONNX file and frozen checkpoint are local ignored artifacts, not included in Git or the normal deployment image. The FP32 model is about 476 MiB and has not been capacity tested in the current Node deployment. Production inference is blocked by the server regardless of the feature flag. Artifact packaging, capacity checks, and staging smoke would not themselves constitute production approval. No production deployment or global enablement was performed.
